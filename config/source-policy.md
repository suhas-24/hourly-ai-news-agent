# Source Policy

## Preference order

The workflow should prefer primary sources whenever possible, including:

- official company announcements
- product release notes or changelogs
- research lab publications
- documentation pages
- regulator, standards, or government publications

Secondary reporting may be used for context, comparison, or coverage expansion when a primary source is unavailable or does not fully explain the development.

## Coverage logging expectations

When possible, each run should record:

- which source categories were checked
- which categories produced usable stories
- which categories were skipped
- which categories were not covered or had no relevant updates

Examples of source categories include:

- company announcements
- research papers
- developer tooling and platform changelogs
- policy and regulation
- security incidents or advisories
- funding, M&A, and partnerships
- major media reporting

## Gaps and skipped sources

If a source category is skipped, unavailable, or produces no meaningful updates, note that in the coverage summary so future runs can distinguish between true no-news periods and incomplete scanning.
